# evalsets — 평가셋 자리 (git 에 올리지 않음)

사진과 정답이 들어 있어 git 에 올리지 않습니다. `generator/` 로 만든 합성 서류를 아래 형식으로 이 폴더에 넣습니다.

```
detector/eval/evalsets/
  평가셋_v3/        예: 정상 97 + 변조 33 (칸 하나 변조)
  평가셋_v4/        예: 정상 97 + 변조 52 (합계까지 맞춘 변조)
  개발지_v1/        기준값을 정할 때 쓰는 개발용 (평가셋으로 기준값을 정하지 않음)
```

- 합성 서류만 넣습니다. 실서류로 만든 평가셋은 외부 AI(OpenRouter)로 읽으면 안 되므로 로직 엔진(로컬 OCR)으로만 잽니다

## 새 평가셋 만들기

형식만 맞으면 합치기 실행기(`detector/pipeline/run.py`) · 채점기(`detector/eval/score_testset.py`)가 그대로 돕니다.

```
detector/eval/evalsets/<새평가셋>/
  문제/                       사진 (예: T001.png — 이름에 정답이 드러나지 않게)
  문제목록.csv                 문제_id · 파일(예: 문제/T001.png) · 문서_종류(영수증 / 진단서) · 가로 · 세로
  정답_채점용/정답.csv          문제_id · 정답(정상 / 변조) · 문서_종류 · 방식 · 내용_모순 · 마스크
  정답_채점용/마스크/           바뀐 곳만 흰색(255)인 PNG. 정답.csv 의 마스크 칸은 '마스크/T001.png' 처럼 정답_채점용/ 기준 (정상은 비움)
```

- 방식 · 내용_모순 · 마스크는 **열만 있으면 되고 값은 비워도 됩니다** (있으면 방식별 점수 · 위치 적중까지 나옴)
- **정상 서류도 꼭 섞기** — 정상이 없으면 오탐을 잴 수 없음
- **합성 서류만.** 실서류 · 1차 변조본으로 만든 평가셋은 AI(외부)로 읽으면 안 됨 → 그런 평가셋은 로직 엔진(로컬 OCR)으로만
- 처음 한 번은 OpenRouter 키로 읽습니다. 응답은 `outputs/combine/vlm_cache/` 에 남아 같은 사진은 다시 돌려도 비용이 들지 않습니다
