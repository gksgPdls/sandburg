# combine — 세 엔진 합치기 (담당 김동현)

세 엔진을 한 번에 돌려 최종 판정 하나를 냅니다. **읽기는 AI(OpenRouter Qwen) 판독값 하나로 통일**하고, 결과는 **병렬**로 모읍니다 (11-06 팀 결정).

```
사진 ─▶ AI 읽기 (한 번, 평가셋/판독값/ 에 저장) ─▶ 동현 검사기 ──┐
                                            └─▶ 혜인 규칙 ────┤─▶ 병렬 결합 ─▶ 최종 판정 + 근거 + 위치
사진 ──────────────────────────────────────────▶ 소영 이미지 ──┘
```

| 파일 | 하는 일 |
|---|---|
| `run.py` | 실행기: 평가셋 → 세 엔진 → 병렬 결합 → 답안 · 채점 |
| `hyein_adapter.py` | AI 판독값 → 혜인 님 `Reading` → 혜인 님 규칙 (혜인 님 코드는 그대로, 행 이름표도 혜인 님 것) |
| `image_engine.py` | 소영 님 `detector.v1.locate()` 그대로 (사진에서 금액 · 날짜 칸을 찾아 흔적 검사, 결과 저장) |

## 실행

```bash
.venv/bin/python combine/run.py testsets/평가셋_v3                      # 세 엔진 (약 1~2분)
.venv/bin/python combine/run.py testsets/평가셋_v3 --이미지없이          # 규칙 엔진 둘만 (몇 초)
.venv/bin/python combine/run.py testsets/평가셋_v3 --처음 10            # 시험 삼아 10장 (평가셋 폴더 · 점수판은 안 건드림)
```

- **키 · 비용 없음**: 평가셋에 저장된 판독값(`판독값/판독값_동현_AI판단_v1.csv`)과 같은 실행의 동현 답안(`답안/답안_동현_AI판단_v1.csv`)을 다시 씀. 평가셋 v3 · v4 · v3_1500 에 들어 있음 (2_평가셋)
- 결과: `평가셋/답안/답안_합침_<혜인규칙 · 규칙둘 · 이미지_<OCR> · 병렬_<OCR>>_v1.csv` → 팀 채점기로 채점(점수판에 한 줄씩), `outputs/combine/<평가셋>_<시각>/요약.md · 엔진별.csv`
- 새 사진은 먼저 AI 로 읽어야 함 (`ai_judge/ai_judge.py`, 키 필요) → 그 판독값으로 이 실행기

## 결합 규칙 (지금: 병렬)

- 규칙 엔진(동현 · 혜인) 중 하나라도 '의심' → **의심** (서식상 반드시 맞아야 하는 계산 · 날짜가 깨진 확실한 근거)
- 아니면 어느 엔진이든 '확인필요' 또는 이미지 '의심' → **확인필요** (예외가 있을 수 있거나 흔적만 있는 약한 근거)
- 셋 다 정상 → **정상**

알게 된 것
1. **혜인 님 규칙은 v4 에서 1장을 더 잡음** (합계까지 맞춘 변조) — 두 규칙 엔진이 빈 곳을 서로 메움
2. **이미지는 지금 상태로는 사람 확인만 늘림**: 정상의 17.5% 를 의심 → 병렬에서 정상 18.6% 가 확인필요 (실서류 9천 장이면 약 1,600장). 칸을 하나도 못 찾는 서류도 22~24% (못 찾으면 '정상')
3. **실서류 해상도에서는 '하나라도 의심이면 의심'이 오탐을 키움**: 두 규칙 엔진이 잘못 읽은 숫자에 서로 다른 서류에서 걸려 오탐 15.5% → 30.9%
   → 저해상도 읽기 보강이 먼저, 결합은 '근거의 확실성'(읽기 확신도 · 같은 칸에 신호가 겹치는지)으로
