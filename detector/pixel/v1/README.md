# detector — 문서 위변조 픽셀 레벨 탐지기

이미지 1장 + 의심 영역(좌표 또는 마스크)만 있으면 동작한다. 원본 문서는 필요 없다.
"의심 영역이 **같은 문서 안의 비슷한 주변 영역**과 다르게 생겼는가"를 여러 관점에서 재고, 종합해서 판정한다.

## 사용법

```bash
# 프로젝트 루트(repo)에서
python -m detector.pixel --image 의심문서.jpg --bbox 937 414 45 12      # x y w h
python -m detector.pixel --image 의심문서.jpg --mask 마스크.png --json
python -m detector.pixel --image 문서.jpg --auto                         # 좌표 없이 자동 탐색 (실험 단계)
```

```python
from detector.pixel import detect
r = detect("의심문서.jpg", bbox=(937, 414, 45, 12))
r["verdict"]["suspicious"]   # True = 위조 의심
r["methods"]["noise"]        # 탐지법별 측정값·판정
```

## 웹 화면

이미지를 올리고 칸을 드래그하면 판정, 탐지법별 결과, 비교 패치와 노이즈 지도가 바로 나온다. 이미지는 이 컴퓨터 밖으로 나가지 않음.

```bash
cd ~/dev/repo
.venv/bin/python -m detector.pixel.web        # http://localhost:8765 가 자동으로 열림
```

또는 Finder에서 `detector/pixel/run/6_탐지기_웹화면.command`를 더블클릭. 추가 설치 없음 (자동 칸 찾기만 tesseract 필요).

## 구조

| 파일 | 역할 |
|---|---|
| `features.py` | 계산식 (ELA, 웨이블릿 노이즈, FFT, 비교 패치 선택 등) — 숫자만 계산 |
| `methods.py` | 탐지법 정의. 탐지법 1개 = 함수 1개, 모두 `{score, inside, outside}` 반환 |
| `config.json` | **판정 기준값, 사용 여부, 근거 수치** — 기준을 바꿀 땐 이 파일만 수정 |
| `core.py` | `measure()`(측정) → `judge()`(판정) → `detect()`(둘을 묶음) |
| `locate.py` | 좌표 없이 OCR로 금액·날짜 칸 자동 탐색 |
| `normal_reference.json` | 정상 문서 측정값 분포 (희귀도 계산용) |
| `__main__.py` | 터미널 CLI |
| `web/` | 웹 화면 (index.html, 분석 서버) |

탐지법 추가: `methods.py`에 함수 추가 + `METHODS`에 등록 → `config.json`에 규칙 추가.

## 공통 원리: "비교 패치"

의심 영역과 크기가 같은 주변 후보(8방향 × 4거리) 중 **밝기와 엣지밀도(선의 양)가 가장 비슷한 패치**를 비교 대상으로 쓴다.
숫자칸은 숫자칸끼리, 표 선은 표 선끼리 비교되게 해서 "내용이 달라서 생기는 차이"를 위조로 오인하지 않게 한다.

## 판단 기준 (2026-10-16 갱신, 1005쌍 / 튜닝 502 · 검증 503 분리)

| 탐지법 | 무엇을 재나 | 위조로 보는 기준 | 정탐 | 미탐 | 오탐 | TN | 정밀도 | 정확도 | AUC |
|---|---|---|---|---|---|---|---|---|---|
| 노이즈분석 `noise` | 웨이블릿 노이즈, 안쪽 ÷ 비교 패치 5개 중앙값 (빈 종이 칸 제외) | **< 0.656** | 327 (65.0%) | 176 | 18 (3.6%) | 485 | 94.8% | 80.7% | 0.88 |
| FFT주파수 `fft` | 고주파 비율 차이, 안쪽 − 비교 패치 | **< −0.032 또는 > 0.190** | 176 (35.0%) | 327 | 8 (1.6%) | 495 | 95.7% | 66.7% | 0.67 |
| 픽셀통계 `pixel_std` | 밝기 표준편차, 안쪽 ÷ 비교 패치 | **< 0.788 또는 > 1.940** | 167 (33.2%) | 336 | 20 (4.0%) | 483 | 89.3% | 64.6% | 0.71 |
| **종합 판정** | 위 3개 중 | **1개 이상** | **427 (84.9%)** | **76** | **42 (8.3%)** | **461** | **91.0%** | **88.3%** | |
| 합성경계분석 `boundary` | 테두리 밝기 변화 ÷ 배경 | 사용 안 함 — 구분력 없음 | | | | | | | 0.53 |
| ELA `ela` | JPEG 재압축 손실 | 사용 안 함 — PNG/JPEG 형식 차이를 잡음 | | | | | | | (0.66) |

정탐·미탐은 검증용 위조본 503장, 오탐·TN은 검증용 정상 원본 503장 기준. 분할을 4번 바꿔도 종합 정확도 88.0~88.3%.

**노이즈 방향 주의:** 위조 영역은 노이즈가 "더 적게" 나온다. 새로 그려 넣은 글자에는 스캔 노이즈가 없기 때문.

**비교 패치 (2026-10-16 개선):** 노이즈분석은 비교 패치 1개 대신 가장 비슷한 5개의 중앙값을 쓰고, 엣지밀도가
의심영역의 절반 미만인 빈 종이 칸은 뺀다. 패치 하나가 빈 칸이나 굵은 글씨 칸으로 잘못 골리면 판정이 틀어졌기 때문
(사례: AIP_0026 미탐, AIP_0046 오탐). 노이즈 AUC 0.817에서 0.881, 종합 정확도 85.7%에서 88.3%.
FFT와 픽셀통계는 여러 개를 쓰면 오히려 나빠져서 1개 유지. (실험: `detector/pixel/scripts/v1/experiments/`)

**희귀도(rarity):** 결과의 `rarity`는 "정상 문서 중 이 값만큼 이상한 비율"(0.02 = 100장 중 2장 수준).
판정 근거 설명과 자동 탐색 시 칸 순위에 쓴다. 정상 분포는 `normal_reference.json` (tune.py --write가 생성).

**종합 방식 실험 결과:** 투표(1개 이상) 유지. 단순 가중합(로지스틱 회귀)은 투표보다 낮았고, 비선형 모델(GBM)은
정확도 +1~2%p였지만 설명이 어렵고 scikit-learn이 필요해 보류.

## 좌표 없이 자동 탐색 (`--auto`, 실험 단계)

OCR(tesseract)로 금액·날짜 칸을 찾아 칸마다 탐지기를 돌리고, 가장 이상한 칸의 희귀도가 `locate.doc_max_rarity`
미만이면 문서를 위조 의심으로 판정한다. 검증용 503쌍 결과 (좌표 입력 없음):

| 항목 | 값 |
|---|---|
| 위조 칸이 OCR 후보에 들어간 비율 | 46.9% (원본 글자는 73%) |
| 가장 의심 칸 = 실제 위조 칸 | 36.2% |
| 문서 정탐 / 오탐 | 26.6% / 9.1% |
| OCR이 위조 칸을 찾은 문서 중 위치까지 정탐 | 44.9% |

아직 실사용 수준 아님. 병목은 OCR — 위조 글자를 OCR이 깨져 읽거나 못 읽음. 숫자 3개 이상인 글자로 후보를 넓히면
포함률은 70.6%로 오르지만 후보가 문서당 6칸에서 21칸으로 늘어 문서 판정은 오히려 나빠짐(정탐 16.9%).
개선 방향: 글자 인식과 무관한 텍스트 영역 검출, 같은 문서 안 다른 숫자 칸들과 비교하는 문서 단위 기준.

## 다시 튜닝·평가하기

```bash
cd detector/pixel/scripts
python evaluate.py --collect   # 이미지에서 측정값 수집 (데이터가 바뀌었을 때만, 수 분)
python tune.py                 # 기준값 후보와 검증 성능 확인 (수 초)
python tune.py --write         # config.json에 반영
python evaluate.py             # 현재 config.json 기준 성능표
python evaluate_locate.py --collect   # 자동 탐색 평가 (OCR 포함, 수십 분)
python debug_case.py AIP_0026          # 탐지기가 무엇과 비교했는지 이미지로 확인
```

## 한계

- 테스트셋은 Stable Diffusion 인페인팅 1종(통장 금액 변경)뿐 — 다른 위조 방식·문서에선 따로 검증 필요.
- 좌표 없는 자동 탐색은 아직 OCR 한계로 실사용 수준 아님.
- 위조 15% 정도는 놓침 (좌표를 줄 때 기준) — 탐지법을 더 추가하거나 합치는 방식(가중 점수 등) 개선 여지.
