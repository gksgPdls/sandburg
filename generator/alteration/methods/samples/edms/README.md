# edms — EDMS 를 거친 것 같은 변형 (재압축·미세 회전·축소)

주 탐지 축: **조작 종류에 따름** · ID: 축 접두어(CM/GL/CL/NM) · 스크립트: [`scripts/make_edms.py`](../../scripts/make_edms.py)

## 조작 방식

회의에서 "보험사 EDMS 를 거치면 압축·재생성된다"고 했다. 실제로 엔진에 들어오는 문서는 이런 상태다. 방법론 문서의 케이스 11(재압축·미세회전 세탁)이다.

**아직 데이터셋에 쓰지 않은 새 원본만 쓴다.** 기존 샘플을 변형하면 같은 문서가 두 번 들어가 평가에서 중복으로 세어지기 때문이다. 새 원본에 자동 조작을 한 뒤 아래 변형을 무작위로 입혔다. 변형 전 버전은 따로 등록하지 않았다.

| 축 | 변형 전 조작 (자동) |
|---|---|
| copy-move 5 | 금액 칸 복제, 숫자 조합 |
| 콘텐츠 로직 5 | 합계 불일치, 자릿수 |
| 글리프 5 | 날짜 치환 |
| 정상 5 | 조작 없음 |

| 변형 | 값 |
|---|---|
| 회전 | ±0.5~2도 (가운데 축, 모서리는 가장자리 색) |
| 축소 | 1.0 또는 0.85배 |
| JPEG 재압축 | 품질 70 / 80 / 90 |

- **원본·조작본·마스크에 같은 변형**을 적용해 해상도와 위치를 맞췄다. 마스크는 최근접 보간 후 0/255 로 다시 맞췄다 (회전한 사각형 모양이 된다)
- `notes`에 조작 종류(`op=`)와 변형 값이 있다

```bash
cd dataset/scripts
../.venv/bin/python make_edms.py --per-axis 5 --normal 5 --seed 0
```

## 무엇을 보는가

- **copy-move:** 회전·재압축 후에도 같은 블록을 찾는가. 블록 매칭은 회전에 약하다
- **글리프:** 재압축으로 획 경계가 뭉개진 뒤에도 폰트 차이를 보는가
- **콘텐츠 로직:** OCR 이 읽기만 하면 모순은 그대로라 영향이 적어야 한다
- **정상 문서:** 압축·회전만으로 위조라고 판정하면 오탐이다

같은 조작 종류의 변형 없는 샘플들과 탐지율을 비교하면 **엔진이 변형에 얼마나 약한지**를 잴 수 있다.
